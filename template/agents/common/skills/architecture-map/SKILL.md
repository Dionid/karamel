# Карта архитектуры

Track A: документ об устройстве системы, а не код. Пишет его роль `architect`
в одноразовом checkout knowledge-репозитория; root оркестрирует, сверяет patch
и отвечает (`AGENTS.md` → «Track A»). Индекс файлов одного репозитория — это
`code-map`, не этот skill.

**Железное правило: каждое архитектурное утверждение подкреплено `path:line`,
командой или URL. Непроверенное не пишется утверждением — оно идёт в раздел
«Неподтверждённое».** Карта, где догадка выглядит так же, как факт, хуже её
отсутствия: следующий агент построит на ней дизайн.

## Куда

Каталог знаний вычисляет skill **`knowledge`** (`resolve.py --task-dir
worktrees/<task>`), не догадка:

```text
<knowledge-root>/architecture/<name>/
  README.md     документ: утверждения с доказательствами + «Неподтверждённое»
  index.html    (необязательно) та же карта визуально; ссылки — <code>path:line</code>
```

`<name>` — kebab-case предмета (`payments`, `ingest-pipeline`). Есть каталог с
тем же предметом — обновляйте его, а не заводите второй.

## Формат README.md

```markdown
# <Предмет>

Срез: <YYYY-MM-DD>, <repo>@<короткий sha>[, <repo>@<sha>…]

## Компоненты и границы
- <утверждение> — `<repo>/<path>:<line>`
- <утверждение> — `rg -n 'listen\(' <repo>/src` → 1 совпадение
- <утверждение> — https://… (дата обращения)

## Потоки
…

## Неподтверждённое
- <что предполагается> — <чем это проверить>
```

- Ссылка на код — inline code `<repo>/<path>:<line>` или `:<start>-<end>`,
  путь от `worktrees/<task>/`; в начале документа — `sha` среза, иначе номера
  строк читатель не воспроизведёт.
- Команда — дословно, с итогом вывода; секреты и значения `.env` не пишутся.
- `host:port` и прочие не-файлы пишите URL-ом: inline `x.y:<число>` проверка
  считает ссылкой на файл.
- Раздел `## Неподтверждённое` обязателен; пусто — один пункт «нет».
- Решения, факты, changelog и инциденты сюда не входят: их ведёт `knowledge`
  внутри своего трека.

## Проверка — до передачи результата

```bash
python3 .claude/skills/architecture-map/check.py --root worktrees/<task> \
  <checkout>/<knowledge-root>/architecture/<name>
```

Exit 0 — все ссылки `path:line` (в `README.md` и `*.html`, вне fenced-блоков)
указывают на существующий файл внутри `--root` и строку в пределах его длины;
пункты «Неподтверждённого» печатаются отдельным списком. Exit 1 — битая ссылка
(`BROKEN README.md:<строка>: …` с причиной), нет `README.md` или раздела.
Битую ссылку чините по коду или переносите утверждение в «Неподтверждённое»;
удалить ссылку, оставив утверждение, — не исправление.

Вывод проверки (дословно) идёт в отчёт `architect` и в closing review:
`reviewer` перезапускает её сам, а не верит отчёту.

## Дальше

Closing review (**`worktree-review`**, затем **`receiving-code-review`**) — до
показа пользователю; закрытие — Draft MR в knowledge-репозиторий через
**`commit-and-mr`**. Понадобились код, тесты, CI/infra или правка слоя агента —
остановитесь и верните задачу на переклассификацию (код → F/C, infra → I,
слой агента → H).

## Красные флаги

- утверждение без `path:line`, команды или URL вне «Неподтверждённого»;
- номера строк без `sha` среза;
- документ в `packages/` или в продуктовом репозитории вместо
  `<knowledge-root>/architecture/`;
- «проверка зелёная», но её вывода нет в отчёте;
- правка кода «заодно», пока пишется карта.
