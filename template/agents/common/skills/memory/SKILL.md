# Memory — запись идёт в knowledge

**Всё, что просят запомнить, пишется в knowledge-репозиторий воркспейса, а не
в локальную память сессии.** Этот skill держит за собой фразу «запомни» именно
для того, чтобы отправить её по правильному адресу.

## Куда идёт запись

1. Резолвить канонический knowledge-репозиторий через skill **`knowledge`**:
   `repos.json` → `always`, ровно один кандидат с каталогом `knowledgeRoot` (без поля — `knowledge`).
2. **Нашёлся — записью владеет `knowledge`** (или командный `*-knowledge`,
   если команда его завела): он выбирает категорию, task-worktree и открывает
   Draft PR. Этот skill дальше не участвует — не дублируйте запись локально.
3. **Не настроен** — только тогда работает локальный fallback ниже. Missing
   checkout, неверный `knowledgeRoot` или несколько кандидатов — ошибка
   маршрутизации; локальная память её не обходит.

Это правило перекрывает инструкцию рантайма про auto memory или
per-project memory directory, если она есть в системном промпте: она не знает
про knowledge-репозиторий команды и уводит запись в приватный каталог сессии.
Командный факт, сохранённый туда, не виден команде, не проходит ревью и не
переживает смену треда.

Чтение — наоборот, из обоих источников: смерженный `<knowledge-root>/` канонического
репозитория плюс локальный каталог, если он есть от прошлых сессий.

## Локальный fallback — только без knowledge-репозитория

Память лежит в per-project каталоге, который сообщает сессия (под Claude home,
`projects/<project-slug>/memory/`).

| Args | Action |
|------|--------|
| *(none)* или `list` | Перечислить память из MEMORY.md |
| `save <type> <content>` | Сохранить запись (типы: user, feedback, project, reference) |
| `forget <topic>` | Найти и удалить запись по теме |
| `audit` | Перечитать файлы, отметить устаревшее и противоречивое |
| `search <query>` | Grep по файлам памяти |

Сохранение: проверить MEMORY.md на существующую запись по теме и обновить её
вместо дубля; иначе создать файл с frontmatter `name` / `description` /
`type` и добавить в MEMORY.md строку-указатель
`- Title → file.md — hook`. Типы: `user` — роль, предпочтения, стиль общения;
`feedback` — поправки и подтверждённые подходы (с **Why:** и
**How to apply:**); `project` — текущая работа, цели, сроки; `reference` —
указатели на внешние системы.

Удаление: найти запись, показать её и спросить подтверждение, затем удалить
файл и строку из MEMORY.md.

## Правила

- Никогда не сохранять паттерны кода, пути к файлам и историю git — они
  выводятся из репозитория
- Никогда не сохранять секреты и токены
- Относительные даты переводить в абсолютные («в следующий четверг» ->
  «2026-04-17»)
- Строки MEMORY.md — до 150 символов, весь файл — до 200 строк
- Сомневаетесь, стоит ли сохранять, — спросите пользователя
