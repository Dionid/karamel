# Запросы к базам данных

**Каждый запрос идёт через [`q.sh`](q.sh).** Он собирает подключение из
кредов корневого .env по имени базы и окружения, применяет защиты ниже в коде,
а не по памяти, и никогда не даёт URI попасть в транскрипт.

```bash
.claude/skills/db-query/q.sh --db <name> --env <dev|prod> --sql "SELECT ..."
```

**Какие базы существуют и что каждая хранит — не в этом файле.** Список
конкретных имён баз, их назначение и переменные `DB_URI_<...>` заводит команда
в `env.example` рядом с этим файлом и в собственной документации. Этот скрипт
не хардкодит ни одного имени базы: `--db <name>` может быть любым именем,
заведённым по конвенции ниже.

## Конвенция имени переменной

```text
DB_URI_<БАЗА>_<ОКРУЖЕНИЕ>
```

`<БАЗА>` — имя из `--db`, приведённое к верхнему регистру; `<ОКРУЖЕНИЕ>` —
`DEV` или `PROD` из `--env`. Например, `--db payments --env prod` читает
`DB_URI_PAYMENTS_PROD`. Имя базы допускает только строчные буквы, цифры и `_`
— это не только соглашение, но и защита в коде: скрипт отказывает на любом
другом символе, чтобы `--db` не мог адресовать произвольную переменную
окружения вместо `DB_URI_*`.

**Выбирайте базу и окружение осознанно.** Когда неясно, какая база владеет
нужной таблицей, назовите, какую собираетесь запросить, и почему. Если нужной
переменной нет в `.env`, `q.sh` выходит с кодом 3 и называет переменную —
**остановитесь здесь**: никогда не собирайте URI вручную из угаданных
хоста/порта/имени базы, не подставляйте URI другой базы и не пробуйте
localhost как запасной вариант.

## Вызов

```bash
.claude/skills/db-query/q.sh --db payments --env prod --sql "SELECT count(*) FROM orders WHERE status = 'pending'" --raw
.claude/skills/db-query/q.sh --db payments --env dev  --sql "SELECT id, status FROM orders ORDER BY id DESC LIMIT 20" --csv
.claude/skills/db-query/q.sh --db payments --env dev   --schema orders        # \d+
.claude/skills/db-query/q.sh --db payments --env dev   --tables              # \dt
.claude/skills/db-query/q.sh --db payments --env prod  --migrations         # накатилась ли миграция?
.claude/skills/db-query/q.sh --db payments --env prod  --whoami             # куда реально подключились?
```

| флаг | что делает |
| --- | --- |
| `--db` / `--env` | какая база и какое окружение — обязательны |
| `--sql` / `--file` | запрос; `--file` для длинного SQL вместо борьбы с кавычками |
| `--csv` / `--tsv` / `--raw` | машиночитаемый вывод (`--raw` — голое значение без заголовков) |
| `--explain` | выполнить `EXPLAIN` вместо запроса — сделайте это перед прод-запросом по большой таблице |
| `--timeout <s>` | `statement_timeout`, дефолт 15 на проде и 60 на dev |
| `--no-limit` | разрешить прод-`SELECT` без `LIMIT` и без агрегата |
| `--confirm` | разрешить запись **на dev** |
| `--print` | показать, что было бы отправлено, и не подключаться |

Называйте базу *и* окружение в любом отчёте о результате («прод payments»,
«dev payments») — строка dev и строка prod не взаимозаменяемое доказательство,
как и строки из двух разных баз. `q.sh` сам печатает эту строку в stderr.

## Что скрипт защищает сам, а что остаётся на вас

Защиты в коде — они падают громко вместо того, чтобы зависеть от того,
вспомните ли вы их:

- **Прод read-only, дважды.** Сервер получает
  `default_transaction_read_only=on`, а сам скрипт отказывает на всём, кроме
  `SELECT`/`WITH`/`EXPLAIN`/`SHOW` — включая `WITH … DELETE … RETURNING`,
  который начинается как будто читает. Код выхода 4. Предложите изменение —
  выполнит человек.
- **Запись на dev требует `--confirm`.** Чтение свободно; с этой базой может
  параллельно работать кто-то ещё.
- **Прод-`SELECT` обязан быть ограничен** — `LIMIT`, агрегат, или отсутствие
  `FROM` вовсе. Иначе код выхода 4 и предложение посчитать вместо выборки.
- **URI никогда не печатается ни в вывод, ни в ошибку.** Значение читается из
  `.env` и передаётся в `psql` только по имени переменной; ошибки называют
  хост и порт, которые назвал сам `psql`, не саму строку подключения.
  **Это не значит, что URI нигде не виден вообще**: `q.sh` передаёт его
  `psql` первым позиционным аргументом, а значит на время выполнения запроса
  строка подключения видна в `ps`/списке процессов той же машины — как и
  любой другой пароль, переданный через argv, а не через файл или переменную
  окружения самого `psql`. На доверенной машине агента это принятый риск;
  не считайте это отсутствием какого-либо локального раскрытия URI.

Всё ещё на вас:

- **Не тащите персональные данные в транскрипт.** Email, телефоны, адреса,
  имена, токены, приватные ключи, seed-фразы, полные дампы пользователей:
  запрашивайте то, что нужно для ответа — `count(*)`, id, статус, timestamp —
  а не `SELECT *` по таблице пользователей. Когда нужна конкретная строка,
  выбирайте конкретные нужные колонки. Никакой скрипт не отличит нужную
  колонку от лишней.
- **Ограничивайте и dev-запросы тоже.** Защита срабатывает только на проде;
  `SELECT *` по большой dev-таблице всё равно плохая идея.
- **Миграция — это изменение, а не запрос.** Даже на dev предлагайте её, а не
  прогоняйте через `--confirm` потому что удобно.

## Настройка

`env.example` объясняет конвенцию имён, но не перечисляет реальные базы
команды — это документирует сама команда рядом со своими репозиториями и
своим `.env.example`. Прежде чем запрашивать базу, проверьте, что переменная
задана, не читая её значение:

```bash
.claude/skills/env-check/env-check.sh DB_URI_<БАЗА>_<ОКРУЖЕНИЕ>
```
