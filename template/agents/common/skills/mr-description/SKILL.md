# PR description

Skill готовит описание по фактическому diff и локально проверяет его. Активный
контур не читает и не изменяет GitHub PR.

Структура из [template.md](template.md) обязательна и идёт в этом порядке:

1. `## Что и зачем`
2. `## Изменения`
3. `## Инфраструктура, схема, зависимости`
4. `## Как проверить`
5. `## Риски и что осталось`
6. `## Changelog`

Первые, вторые и четвёртые секции должны содержать факты, а не `Нет`.
`## Changelog` — путь записи changelog внутри knowledge-репозитория и её
заголовок; что туда писать и нужна ли запись вообще, решает skill
**`changelog`** (живёт в knowledge-репозитории), и он же даёт проверенный
путь. Секция
обязательна, но честное «Нет» в ней допустимо: вопрос должен быть задан в
каждом PR, а выдумывать запись ради заполненной строки — нет. URL PR
knowledge-репозитория здесь не нужен: его проставит блок задачи, когда тот PR
появится.

Плейсхолдеры запрещены. Управляемые блоки `spec-link` и `task-link` в авторском
описании запрещены тоже, и это не значит, что их не будет в PR: `commit-and-mr`
сам добавляет их над авторским текстом в момент создания PR
([task-link.md](../commit-and-mr/task-link.md)). Пишите только свои шесть секций
— автора, ссылки на соседние PR задачи и спеку не дублируйте руками.

```bash
.claude/skills/mr-description/describe.sh check --file /tmp/mr-description.md
```

`DESCRIPTION_OK=true` означает только корректную структуру. Каждое
утверждение всё равно сверяйте с diff, log и свежими результатами проверок.
`commit-and-mr` запускает тот же gate перед staging.

Описание уже открытого PR читает `gh pr view <ветка> -R <origin> --json state,body`
(поле `body`). Прочитанный текст несёт управляемые блоки, которые
`check` отвергает, поэтому перед правкой и проверкой их снимает `strip`:

```bash
.claude/skills/mr-description/describe.sh strip --file /tmp/mr-readback.md > /tmp/mr-description.md
```

Заменяет описание без нового коммита и push режим
`commit-and-mr/run.sh --worktree <checkout> --repo <repo> --existing-mr
--mr-description-file <file> --description-only` — без путей и
`--message-file` ([run-sh.md](../commit-and-mr/run-sh.md)). `run.sh` и сам
снимает целые управляемые блоки перед проверкой и рисует их заново, так что
дублей не будет; незакрытый маркер он не угадывает и отказывает.
