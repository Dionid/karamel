# `task-link.sh` — кто написал и какие ещё PR у задачи

Справка к блоку, который `run.sh` сам добавляет в описание PR. Режимов два:
офлайн-рендер (stdout, без сети) и живое обновление `--update` через gh.

```bash
# офлайн: блок для описания создаваемого PR
.claude/skills/commit-and-mr/task-link.sh --task <task> --self worktrees/<task>/<repo>
# живой проход: переписать блок во всех открытых PR задачи
.claude/skills/commit-and-mr/task-link.sh --task <task> --update [--dry-run]
```

## Что пишет `--update`

Один управляемый блок на каждый открытый PR задачи, между
`<!-- task-link:start -->` и `<!-- task-link:end -->`:

```markdown
<!-- task-link:start -->
### Задача `payout-timeout`

**Автор:** `managed runtime agent <author@example.com>` · агент: `Claude Opus 5 (1M context)`

Эта задача разложена на несколько репозиториев — вот все её PR:

| Репозиторий | Ветка | PR |
| --- | --- | --- |
| backend | `feature/payout-timeout` | [#234](https://github.com/org/backend/pull/234) · opened ← этот PR |
| shared-lib | `feature/payout-timeout` | [#153](https://github.com/org/shared-lib/pull/153) · opened |
| agent-workspace | `feature/payout-timeout` | _MR не открыт_ |

_Таблицу обновляет `task-link.sh --update` при каждом PR задачи, …_
<!-- task-link:end -->
```

- **Автор берётся из коммитов ветки**, а не из `git config`: различные
  `%an <%ae>` на `origin/<base>..HEAD`, поэтому ветка, в которую пушили двое,
  называет обоих. Агент — из трейлера `Co-Authored-By`, который дописывает
  `run.sh`; это единственная запись о том, какая модель сделала коммит.
- **PR каждого чекаута ищет gh** (`gh pr list --head <ветка>
  --state all`): открытый, а если его нет — последний в любом состоянии. Смёрженный
  или закрытый PR остаётся строкой в таблицах соседей, но его описание не
  переписывается.
- **В таблице каждый чекаут задачи, который несёт работу.** Чекаут, добавленный
  `wt new` из `repos.json.always` и задачей не тронутый, коммитов впереди базы
  не имеет и в таблицу не попадает.
- **У задачи из одного репозитория таблицы нет** — только строка автора.

Переписывается только блок: текст, написанный человеком вокруг него, и
spec-блок остаются как были. Повторный запуск, когда блок уже верен, печатает
`UNCHANGED=` и ничего не отправляет.

## Офлайн-рендер

Без `--update` скрипт только печатает блок: ни gh, ни сети. `run.sh` кладёт
его в описание, с которым PR создаётся, — строка этого PR там `_этот MR_` без
ссылки, а соседи берутся из локальных записей coordination. Сразу после
создания `run.sh` зовёт `--update`, и офлайн-таблица заменяется живой. Если
`--update` не прошёл, офлайн-блок сам говорит, что он собран до создания PR.

`--stale-siblings` печатает URL открытых PR задачи из локальных записей
coordination, кроме `--self`, — по одному на строку.

## Вывод `--update`

`LINKED=` / `UNCHANGED=` / `SKIPPED=` по чекаутам, затем `TASK_MRS=`,
`TASK_LINKED=`, `TASK_UNCHANGED=` и `TASK_FAILED=`. Код возврата ненулевой,
только если поиск или запись не удались. `--quiet` оставляет одни ошибки.

| строка | смысл |
| --- | --- |
| `SKIPPED=<repo> no-mr` | ветка несёт коммиты, но PR ещё нет — повторите, когда появится |
| `SKIPPED=<repo> mr-merged` / `mr-closed` | история; строка остаётся в таблицах соседей |
| `SKIPPED=<repo> detached-head` | не на ветке — искать нечего |
| `FAILED=<repo> lookup` | gh не смог перечислить PR ветки — логин или сеть |
| `FAILED=<repo> <url>` | gh отказал в правке описания |
| `FAILED=<repo> <url> ambiguous-markers` | в описании два живых маркера или маркер спрятан незакрытым fence |

`FAILED=` с 403 означает, что токен может читать PR, но не править их. Это не
обходится: доложите, отдайте пользователю блок из `--dry-run` и дайте ему
вставить его или расширить токен.

## Границы

- Заголовок, Draft, labels, assignees и всё вне своего блока скрипт не трогает
  и PR не открывает.
- Маркеры `<!-- task-link:start -->` / `<!-- task-link:end -->` помечают блок
  как сгенерированный. В авторском описании они запрещены, и
  `mr-description/describe.sh check` отвергает файл с ними: описание проверяется
  до того, как блок добавлен. Описание, прочитанное обратно из GitHub, их
  несёт: `run.sh` снимает целые блоки перед проверкой и рисует заново, вручную
  их снимает `describe.sh strip`.
- Чекаут, удалённый с диска, в таблицу не попадёт, даже если его PR открыт:
  таблица строится по живым чекаутам задачи.
