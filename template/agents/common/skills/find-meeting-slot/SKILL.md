# Find Meeting Slot

Пользователь даёт **сроки** («на этой неделе»/«на следующей»/конкретные даты)
и **участников**. Скилл резолвит их почты и таймзоны, смотрит занятость по
календарям, находит **общие свободные слоты** в рабочем окне и предлагает
варианты.

## Когда использовать

- «собери мид на след. неделе, проверь X, Y, Z»
- «когда всем удобно встретиться», «найди слот для созвона с X, Y»
- НЕ для: обработки прошедшей встречи (см. `post-meeting`), заведения задач
  из переписки.

## Требуемые источники — без них честный отказ

Этому скиллу нужны **подключённые** календарный MCP (free/busy) и,
опционально, Slack/чат MCP (резолв участников по тегу/имени в профиль). Если
нужный MCP не подключён или недоступен — сказать это прямо и не подбирать
слот вслепую по догадкам о занятости. Не изобретать доступность людей.

## Пайплайн

### 1. Разобрать запрос

- **Участники**: теги/упоминания из текста, либо имена — резолвить через
  доступный справочник команды, затем через поиск в чат-MCP.
- **Инициатор**: включать по умолчанию, если это его встреча; исключить,
  только если сказано «без меня» / «между ними».
- **Сроки**: «эта неделя» / «следующая неделя» / «завтра» / явные даты →
  передать в скрипт как `range` (`this_week` | `next_week` | `today` |
  `tomorrow` | `{"from","to"}`). Скрипт сам разворачивает в будни
  относительно `now`.
- **Длительность**: детект из текста («на час»/«30 минут»). Дефолт — 30 мин.

### 2. Резолвить каждого участника

Через доступный профиль (чат-MCP или справочник команды) →
`{name, email, tz, status}`.

- Статус вроде отпуска/отсутствия → пометить флагом и предупредить
  пользователя («X в отпуске — точно зовём?»). Не выбрасывать молча.
- `tz` нужна для рабочего окна; `email` — ключ календаря.

### 3. Тянуть занятость

Для **каждого** участника **отдельным** вызовом free/busy на весь диапазон.
Вызовы можно слать параллельно.

- Один недоступный/битый календарь не должен ронять весь запрос — вызывать
  строго по одному участнику за раз. Если календарь недоступен →
  `busy: null` в payload (скрипт пометит «календарь недоступен, не учтён»),
  не падать.
- Время `timeMin`/`timeMax` — с суффиксом `Z` (UTC). Ответ обычно приходит в
  UTC.

### 4. Посчитать слоты (детерминированно, не в голове)

Собрать `payload.json` и вызвать:

```bash
python3 .claude/skills/find-meeting-slot/slot_finder.py --input payload.json
```

`slot_finder.py` tz-aware, на stdlib (`zoneinfo`), сети не касается:
- разворачивает сроки в будни (выходные/прошедшие дни и прошедшие сегодня
  часы + лид-буфер 60 мин отсекаются);
- строит окно дня = базовое окно (по умолчанию `MEETING_TZ` из `.env`, иначе
  UTC) ∩ локальное 10-18 (или 9-19) **каждого** участника в его tz → слот
  обязан быть рабочим и по базовой таймзоне, и локально у всех;
- вычитает занятость, находит свободные ≥ длительности;
- ранжирует: сперва где свободны ВСЕ → идеальное окно над расширенным →
  раньше = лучше;
- near-miss: слоты, где занят ровно один участник (кого можно подвинуть или
  позвать без него);
- печатает человекочитаемый отчёт плюс машинный блок
  `===JSON===...===END===` для форматирования ответа.

### 5. Отдать результат

- Показать таблицу участников + ранжированные слоты.
- **Личные ID/почты в ответ не тащить сверх необходимого** — участников
  называть по имени, email оставлять только как техническую деталь при
  необходимости.
- **Событие в календаре не создаётся автоматически** — приглашения уходят
  всем, это последствие, требующее согласия. Только по явной команде
  («создай», «поставь встречу») и после подтверждения конкретного слота —
  создание идёт через тот же подключённый календарный MCP.

## Таймзоны

- База — `MEETING_TZ` из `.env` (например `Europe/Moscow`); без неё —
  UTC. Проверить через
  `.claude/skills/env-check/env-check.sh MEETING_TZ`.
- Инициатор — якорь базовой таймзоны по умолчанию, если он сам задал
  «по нашему времени»; если он говорит «учитывай моё локальное» — дать его
  реальную tz в payload, тогда его окно тоже сузит расчёт.
- Остальные участники всегда считаются по своей tz: слот попадает в 10-18
  (или 9-19) local у каждого. Для tz, отличной от базовой, скрипт печатает
  локальную подсказку.
- Всё tz-aware через `zoneinfo` — оффсеты и DST не хардкодятся.

## Дефолты (сводка)

| Параметр | Дефолт | Как поменять |
|----------|--------|--------------|
| Длительность | 30 мин | `duration_min` в payload |
| Идеальное окно | 10-18 базовой tz | `ideal_window` |
| Запасное окно | 9-19 базовой tz | `extended_window` |
| Лид-буфер (не раньше чем) | 60 мин от now | `lead_min` |
| Только будни | да | `workdays_only: false` |
| Событие в календаре | не создаётся | явная команда + согласие |

## Verification

1. **Спот-чек слота.** Для 1-2 предложенных «все свободны» слотов сверить
   вручную: у каждого участника этот интервал реально вне его busy-блоков
   из сырого free/busy. Скрипт печатает `free/busy/unknown` по каждому
   слоту в `===JSON===` — сверить.
2. **Проверка как пользователь.** Слот в идеальном окне лежит и в базовом
   окне, и в локальном окне каждого участника.
3. **Adversarial:**
   - участник в далёкой tz → окно сузилось, а не выдало нерабочее время;
   - участник без календаря (`busy:null`) → помечен «недоступен», расчёт не
     упал;
   - нет полного пересечения → сработал near-miss или честное «пересечения
     нет»;
   - «эта неделя» под конец рабочей недели/дня → прошедшие часы и дни
     отсеклись (лид-буфер);
   - участник в отпуске/недоступен по статусу → предупреждение выдано.
4. **Freebusy по одному** (не батчем) — иначе один битый календарь роняет
   весь расчёт.
