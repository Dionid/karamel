# Slack MCP

**Slack — внешнее состояние команды: чтение свободно, запись — только после
явного согласия пользователя на точный канал/тред и текст сообщения.**

Используйте инструменты MCP настроенного сервера `slack`, обычно они видны как
`mcp__slack__*`. Пока сервер доступен, не заменяйте его веб-скрейпингом или
самодельными вызовами API.

## Прежде чем этот скилл заработает — регистрация сервера

Скрипты здесь дают серверу токен и кеш; **саму запись `mcpServers.slack`**
(или `mcp_servers.slack` для Codex) команда добавляет в свой собственный слой
конфигурации — `agents/claude/settings.json` / `agents/codex/config.base.toml`
её команды, а не в базовый слой движка. Путь до `mcp-server.sh` пишется как
`@ROOT@/…` — **не** `$CLAUDE_PROJECT_DIR/…`: harness сам подставляет `@ROOT@`
абсолютным путём воркспейса на сборке (`expandRoot` в `src/core/build.ts`),
а `$CLAUDE_PROJECT_DIR` — переменная окружения самого Claude Code, которую
harness в собранный `settings.json`/`.mcp.json` не прокидывает и никак не
разворачивает; команда, буквально вписанная с `$CLAUDE_PROJECT_DIR`, уйдёт в
файл как есть и не раскроется ни в одном рантайме.

Для Claude Code — запись в `agents/claude/settings.json` команды:

```json
{
  "mcpServers": {
    "slack": {
      "command": "@ROOT@/.claude/skills/slack/mcp-server.sh",
      "args": []
    }
  }
}
```

Для Codex — запись в `agents/codex/config.base.toml` (или `config.append.toml`)
команды:

```toml
[mcp_servers.slack]
command = "@ROOT@/.agents/skills/slack/mcp-server.sh"
args = []
```

Это ровно та точка расширения, которую `./ops sync`/`./ops sync` уже
поддерживает: `settings.base.json` слоя движка сливается с командным
`settings.json`, и всё, что окажется в объединённом `mcpServers`, само
выносится в `.mcp.json` с уже раскрытым `@ROOT@`. Codex получает свою запись
тем же путём через `agents/codex/config.*.toml`. Без этого шага скилл
установлен, но сервер не запущен ни в одном рантайме — это ручной шаг
команды, не движка.

## Конфигурация в среде исполнения

Оба рантайма запускают сервер через одну обёртку — `mcp-server.sh` этого
скилла, которая читает корневой `.env` и запускает
`npx -y slack-mcp-server@latest --transport stdio`. Хотя бы одно из этих двух
имён должно быть задано, в `.env` или экспортировано в окружении:

```bash
SLACK_MCP_XOXP_TOKEN=...
SLACK_MCP_XOXB_TOKEN=...
```

**`SLACK_BOT_TOKEN` — не одно из них.** `slack-mcp-server` читает только два
имени выше; проверьте задание переменных без чтения значений:

```bash
.claude/skills/env-check/env-check.sh SLACK_MCP_XOXP_TOKEN SLACK_MCP_XOXB_TOKEN
```

**Обёртка существует потому, что `.env` и окружение процесса CLI — две разные
двери.** `${VAR}` в конфиге рантайма подставляется из окружения самого CLI, а
некоторые хостинговые рантаймы дают этому процессу ограниченное окружение для
MCP-серверов, которое не несёт ничего из `.env` воркспейса. Сервер, объявленный
как `${SLACK_MCP_XOXB_TOKEN}`, тогда стартует с пустым токеном, как бы полно ни
был заполнен файл, и падает так, будто креда вообще нет. Чтение файла в
обёртке закрывает этот разрыв; наружу уходят только два имени Slack, так что
npm-пакет не наследует ничего лишнего.

Предпочитайте `SLACK_MCP_XOXP_TOKEN` для поиска и истории каналов от лица
пользователя. Бот-токен годится для задач в рамках бота, но видит только те
каналы, куда его пригласили, и не поддерживает часть путей поиска. Если
инструментов Slack нет или авторизация не проходит, спросите у обёртки, а не у
догадки — она печатает имена, пути кешей и `set`/`missing`, никогда значение:

```bash
.claude/skills/slack/mcp-server.sh --print
```

## Кеш каналов — требование загрузки, а не оптимизация

**Отсутствующий кеш каналов фатален, и сервер не всегда может построить его
сам.** `slack-mcp-server` запрашивает все четыре типа переписки одним вызовом
`conversations.list`, так что токен без `im:read` или `mpim:read` роняет весь
запрос — а загрузка с нулём каналов и без файла кеша на диске заканчивается
`Error booting provider: API returned zero channels and no existing cache is
available`. Для рантайма это выглядит как `CONNECTION_CLOSED` у сервера, чей
токен секунду назад прекрасно авторизовался.

Стройте кеш по типам вместо одного запроса — это то, что токен может:

```bash
.claude/skills/slack/refresh-cache.sh            # пропускает типы, которые нельзя прочитать
.claude/skills/slack/refresh-cache.sh --print    # пути и наличие, без сети
```

Нужен `SLACK_MCP_XOXP_TOKEN`; бот-токен построил бы кеш только с каналами,
куда бота пригласили, скрыв остальные. На большом воркспейсе это минуты (в
основном ожидание `429`), поэтому обёртка сама этот скрипт не вызывает — MCP-
клиент даёт серверу секунды на ответ на `initialize`.

**Оба кеша живут вне `$HOME`, если рантайм предлагает что-то устойчивое** —
`SLACK_MCP_CACHE_DIR`, иначе `WORKSPACE_CACHE_DIR`, иначе дефолт самого сервера.
На части хостинговых рантаймов `$HOME` привязан к одной сессии, так что кеш,
построенный там, умирает вместе с сессией, которая его построила, а
пользовательский кеш при этом тихо пересобирается каждый раз — из-за этого
сбой и выглядел прерывистым.

## Процедура чтения

1. Определите канал, пользователя или тред через инструменты Slack MCP, прежде
   чем читать историю. Не угадывайте id канала по памяти о его имени.
2. Ограничьте запрос временем, каналом, пользователем, автором или поисковыми
   терминами. По умолчанию — самое узкое окно, которое отвечает на вопрос.
3. Резюмируйте находки со стабильными ссылками: имя канала, timestamp
   сообщения, отображаемое имя автора, контекст треда.
4. Цитируйте минимум текста, необходимый как доказательство. В Slack могут
   быть персональные данные, секреты, детали клиентов, приватный операционный
   контекст.

## Запись

Перед любой публикацией, ответом, реакцией, изменением канала, юзергруппы или
другой записью в Slack — спросите явное согласие и назовите:

- целевой канал или тред;
- точный текст сообщения или действие;
- от чьего лица оно уйдёт — пользователя или бота, в зависимости от токена.

После согласия выполните MCP-запись один раз, затем перечитайте результат,
если инструмент это позволяет, и доложите permalink или timestamp.

Оформление текста — по
[`references/interaction-rules.md`](references/interaction-rules.md):
mrkdwn вместо обычного markdown, treading, tag-back, длина сообщения. Это
справочник по форме, а не разрешение писать без согласия из абзаца выше.

## Границы

- Не создавайте Slack-приложения, не ротируйте токены и не меняйте настройки
  воркспейса Slack из этого скилла.
- Не вставляйте целые треды или длинные дампы сообщений в ответ; резюмируйте и
  цитируйте конкретные использованные сообщения.
- Не отправляйте в Slack секреты, креды, приватные ключи, строки подключения к
  БД или сырые значения `.env`.
- Если Slack MCP не подключён в текущей сессии — скажите об этом, запустите
  `--print` выше, чтобы назвать, какого из двух имён не хватает **и есть ли
  кеш каналов**, и попросите пользователя это поправить и перезапустить сессию
  — MCP-серверы стартуют один раз за сессию.
