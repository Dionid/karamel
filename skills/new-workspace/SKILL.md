# Новый воркспейс

Скрипт рядом со скиллом копирует `template/` из корня karamel, генерирует
командные файлы и собирает рантайм:

```bash
<karamel>/skills/new-workspace/new-workspace.sh create <dir> --team <name> \
  [--knowledge <name>=<url>[@<branch>]] [--repo <name>=<url>[@<branch>]]... \
  [--agent <name>] [--branch-prefix codex/] [--no-setup] [--no-clone] [--no-git]
```

`<karamel>` — каталог этого репозитория или установленного плагина: путь к
скрипту — `skills/new-workspace/new-workspace.sh` относительно него.

## Перед запуском спросите у пользователя

1. Каталог, в котором создать воркспейс. Он должен быть пустым или не
   существовать.
2. Имя команды (`--team`).
3. Репозиторий знаний и спек, если есть (`--knowledge`). Он попадает в
   `repos.json.always` и подключается к каждой задаче, поэтому у него должен
   быть хотя бы один коммит на базовой ветке.
4. Продуктовые репозитории (`--repo`, по одному флагу на репо). Базовая ветка
   по умолчанию `main`; другая указывается через `@<branch>`.

Не угадывайте URL репозиториев: спросите или возьмите из того, что
пользователь уже дал.

## Что делает `create`

1. Копирует шаблон: `agents/`, `ops`, `AGENTS.md`, `GIT.md`, `WORKTREES.md`,
   CI и остальное.
2. Пишет `workspace.json`, `repos.json`, `PACKAGES.md`, заголовок `README.md`.
3. Делает `git init -b main` и первый коммит (без коммита, если не настроен
   git identity).
4. Запускает `./ops setup`: собирает `.claude/`, `.agents/`, `.codex/`,
   `harness.json`, ставит git-хуки, копирует `.env.example` в `.env`.
5. Клонирует репозитории в `packages/` через `./ops clone`, если задан
   `GITHUB_TOKEN` (в окружении или в `.env`). Иначе пропускает шаг с подсказкой.
6. Проверяет результат `./ops check`.

Значения из `.env` скрипт не читает и не печатает: он только проверяет, что
строка `GITHUB_TOKEN=` непустая.

## Обновление созданного воркспейса

```bash
<karamel>/skills/new-workspace/new-workspace.sh upgrade <dir> [--dry-run]
```

Перезаписывает общий слой из шаблона и удаляет из `agents/` и `docs/` файлы,
которых в шаблоне больше нет. Командные файлы не трогает никогда:
`repos.json`, `workspace.json`, `PACKAGES.md`, `README.md`, `notion.json`,
`CODEOWNERS`, `IDENTITY.md`, `SOUL.md`, `AGENTS.md`, `.env.example`. Если в
шаблоне изменились `AGENTS.md` или другие командные файлы, скрипт печатает
`keep … сверьте вручную`, и сверку делаете вы.

Скрипт отказывается работать при незакоммиченных правках в воркспейсе: diff
обновления должен быть отдельным. После него выполните `./ops sync`,
`./ops check` и откройте обычный PR в репозитории воркспейса, следуя его
`AGENTS.md`.

## Чего скрипт не делает

- Не создаёт репозиторий на GitHub и не пушит: это делает пользователь (или
  `gh repo create`, если пользователь об этом попросил).
- Не заполняет `.env`.
- Не правит раздел «Правила команды» в `AGENTS.md`: это решение команды.
